# 問題の書き方

問題は Python のモジュールに `SECTIONS`（分野の一覧）として書きます。見本は [example/questions.py](../example/questions.py)。

## 分野

```python
SECTIONS = [
    dict(id='s1', title='データ型と演算', scenario='', questions=[ ... ]),
]
```

| 項目 | 内容 |
|---|---|
| `id` | 分野のID。問題集の中で重ならない短い文字列 |
| `title` | 分野名。問題の見出しと成績の表に出る |
| `scenario` | 問題の上に出す状況説明（任意）。開閉でき、開いているかはブラウザに覚える |
| `rate` | 分野ごとに出す数値（任意。`build(rate_label='配点')` を渡したときだけ成績の表に出る） |
| `lesson` | 分野の解説カード（任意）。`dict(lead='一文の要点', points=[('見出し', '本文'), ...], fig=図)`。分野の問題の前に出る |
| `questions` | 問題の一覧 |

## 問題

| 項目 | 内容 |
|---|---|
| `id` | 問題のID。問題集全体で重ならない文字列。記録の保存に使うので、公開後は変えない |
| `stem` | 問題文。2字下げした行のかたまりは等幅のコード枠になる。列が2つ以上そろっていれば表になる（1行目が見出し） |
| `opts` | 選択肢。単一選択は4つ、複数選択は5つ |
| `ans` | 正解の添字（0始まり）。リストにすると「その数だけ選ぶ」複数選択になる（例 `[0, 2]`） |
| `trap` | いちばん迷いやすい誤答の添字。画面で「次点」と出る |
| `why` | 正解の理由 |
| `trapwhy` | 次点が落ちる理由 |
| `rest` | 残りの選択肢が外れる理由。`{添字: 理由}`。正解と次点以外の全部を書く |
| `deep` | もう一歩踏み込んだ解説（任意。背景、似た場面での見分け方） |
| `fig` | 解説に入れる図（任意）。下の「図」を参照 |

選択肢の表示順は問題ごとに固定のシャッフルがかかるので、正解を書く位置を気にしなくて構いません。

## 解説の書き方

解説カードを作らずに、各問の解説だけで範囲の知識が一通り揃うようにすると、解くだけで学べる問題集になります。

1. 出題範囲の目標を一覧にする
2. 目標ごとに、それを問う問題を割り当てる。取りこぼした目標が無いことを表で確かめる
3. 各問の `why` / `trapwhy` / `rest` に加えて、`deep` にその目標を答えるのに要る前提知識を書く

## 図

`drillkit/figs.py` の関数で組みます。図は HTML と CSS で描くので、スマホ幅でも文字が折り返して読めます。

| 関数 | 使いどころ |
|---|---|
| `flow(cap, steps, end=None, h=False)` | 手順・データの流れ。`end` で最後に枝分かれ |
| `cycle(cap, steps, back)` | ループ |
| `vs(cap, ng, ok)` | よくある誤りと正しい形の対比 |
| `layers(cap, rows, hl=None)` | 重なる層・選択肢の棚 |
| `hub(cap, top, kids, bottom=None)` | 親と子、子の結果の集約 |
| `matrix(cap, cols, rows)` | 条件×選択肢の早見表。セルの先頭に ○ × △ で色が付く |
| `bars(cap, items, unit='')` | 数値の比較 |

各要素は `(見出し, 補足)` か `(見出し, 補足, 'ok'|'ng'|'key')`。文字は短くし、見出しは全角12字前後、補足は全角30字前後を目安にします。

## 書き終えたら

`build()` は次の書き漏れを警告します：選択肢の数、正解に次点が含まれている、`rest` の添字の過不足、`why` / `trapwhy` の欠け、IDの重複。
